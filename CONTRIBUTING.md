# Contributing to metaCAMPUS

Thank you for your interest in contributing! Please follow these guidelines to help us maintain a secure, high-quality, and collaborative project.

## Branching & Workflow
- All development must occur on a dev branch named with your username and a short task description (e.g., `charles/auth-middleware`).
- Never commit directly to `master` or `main`.
- Each commit should be small, intentional, and attributable to a single developer.
- All work must be reviewed via pull request before merging.

## Code Standards
- Match existing code style and naming conventions.
- Do not introduce new frameworks or abstractions without approval.
- Keep changes focused and avoid drive-by refactors.
- All new code must pass linting and tests before review.

## Security & Compliance
- Never commit secrets, credentials, or sensitive data.
- Follow the security policy in SECURITY.md.
- Report vulnerabilities as described in SECURITY.md.

## Communication
- Use clear, descriptive commit messages and PR titles.
- Reference related issues or tasks in your PRs.
- If requirements are unclear, ask for clarification before coding.

## Testing
- Add or update tests for all new features and bug fixes.
- Ensure all tests pass locally before submitting a PR.

---
For questions, contact the SCRUM lead or project maintainers.
